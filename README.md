# Сервис учета городских событий (City Events Service)

Консольное приложение для хранения и просмотра городских событий. Оно позволяет
просматривать и искать события, фильтровать их по дате и категории, вести
справочники мест и категорий, регистрировать участников и отменять регистрации.
Данные сохраняются между запусками в JSON-файлах.

## Предметная область и объектная модель

Коллекции приложения содержат экземпляры классов из `models/`:

| Класс | Атрибуты | Поведение |
| --- | --- | --- |
| `Place` | `id`, `name`, `address` | `from_data()`, `__str__()` |
| `Category` | `id`, `name`, `description` | `from_data()`, `__str__()` |
| `User` | `id`, `name` | `from_data()`, `__str__()` |
| `Event` | `id`, `title`, `place`, `category`, `event_date` | `from_data()`, `get_status()`, `__str__()` |
| `Registration` | `id`, `event`, `user`, `is_cancelled` | `cancel()`, `__str__()` |

`Event` хранит ссылки на объекты `Place` и `Category`. `Registration` связывает
объект `Event` с `User`. Отмена изменяет состояние регистрации, сохраняя её в
истории. Повторная активная регистрация на то же событие запрещена, а после
отмены можно зарегистрироваться снова.

Конструкторы классов задают состояние объектов, методы работают с этим
состоянием, а `__str__()` обеспечивает читаемый вывод. Состояние отмены
регистрации инкапсулировано: `is_cancelled` доступен только для чтения,
изменение выполняется методом `cancel()`. Классы не используют наследование,
поскольку сущности предметной области не являются разновидностями друг друга.
Единый интерфейс `__str__()` демонстрирует полиморфное строковое представление.

## Основные операции

- просмотр событий, мест, категорий и регистраций;
- поиск событий по названию и мест по названию или адресу;
- фильтрация событий по категории и дате, сортировка по дате;
- добавление мест, категорий и событий;
- создание и отмена регистрации участника;
- определение статуса события относительно текущей даты.

Функции модулей `places.py`, `categories.py`, `events.py` и `registrations.py`
выполняют операции над коллекциями объектов. Поведение отдельных сущностей
находится в методах соответствующих классов.

## Хранение данных

`storage.py` отвечает за сериализацию. При загрузке записи JSON превращаются в
объекты и связываются по идентификаторам. При сохранении внешние связи
сериализуются как `place_id`, `category_id`, `event_id` и `user_id`.

Используются файлы:

- `data/places.json` — места;
- `data/categories.json` — категории;
- `data/events.json` — события и id места/категории;
- `data/users.json` — участники;
- `data/registrations.json` — регистрации и id события/пользователя.

Загрузчик также читает прежние данные ПР2 в виде JSON-словарей и регистрации,
содержащие только `user_name`. Такие участники преобразуются в объекты `User`.

## Структура проекта

```text
city-events-service/
├── main.py
├── storage.py
├── utils.py
├── places.py
├── categories.py
├── events.py
├── registrations.py
├── models/
│   ├── __init__.py
│   ├── places.py
│   ├── categories.py
│   ├── users.py
│   ├── events.py
│   └── registrations.py
├── data/
│   ├── places.json
│   ├── categories.json
│   ├── events.json
│   ├── users.json
│   └── registrations.json
└── tests/
    ├── test_places.py
    ├── test_events.py
    ├── test_registrations.py
    └── test_storage.py
```

- `main.py` — меню и пользовательские сценарии;
- `models/` — классы предметной области;
- корневые модули сущностей — функции для работы с коллекциями объектов;
- `storage.py` — JSON-загрузка/сохранение и восстановление связей;
- `utils.py` — ввод данных с проверкой ошибок;
- `tests/` — автоматические тесты pytest.

## Запуск

Требуется Python 3.10 или новее.

```bash
python main.py
```

## Тестирование и качество кода

```bash
pytest -v
flake8 .
```

Тесты проверяют атрибуты и строковое представление объектов, работу методов,
операции над коллекциями, правила регистрации, восстановление объектных связей
из JSON и совместимость со старыми файлами.
